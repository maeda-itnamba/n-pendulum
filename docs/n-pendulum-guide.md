# n重振り子シミュレーター 開発課題ガイド

作成：辻村 明（2026年11月16日）

## この課題について

n重振り子（振り子をn個つないだもの。n＝2が二重振り子）の動きを計算して、ブラウザで美しく見せるWebアプリを、AIと一緒に作る課題です。計算はPython、画面はTypeScriptで作ります。

ゴールは3つあります。

- 物理として正しく動くn重振り子を、だれでもURLから見られる形で公開する
- 環境構築から公開まで、仕事と同じ流れを一通り経験する
- AIに何を頼み、自分で何を確かめたかを、文章で説明できるようになる

進め方の約束です。

- やりとりはすべて文章で行います。返事は急がなくて大丈夫です
- AI（Claudeなど）は自由に使ってください。使い方そのものが、この課題で見たいところです
- 各ステップの終わりに短い報告を送ってください。確認してから次のステップに進みます
- 迷ったら、止まる前に質問してください。「AかBで迷っています」という形だと答えやすいです
- 期間は全体で4〜5週間を目安にしていますが、自分のペースで進めてください

## 進め方のポイント（AIとの役割分担）

AIを「司令塔」と「実装・操作」の2つの役割で使い分けます。

| 役割 | 使う場所 | モデル | やること |
| --- | --- | --- | --- |
| 司令塔 | ClaudeのデスクトップアプリまたはWeb（claude.ai）で作った、この課題用のプロジェクト | Opus 5.5。重要な場面ではFable | 計画を立てる、設計を相談する、困ったときに相談する |
| 実装・操作 | VS Codeの拡張機能で入れたClaude（Claude Code） | Sonnet | コードを書く、テストを動かす、ターミナルを操作する |

Fableは使える回数が少なく、追加のクレジットが必要になることがあります。設計の大事な判断など、ここぞという場面だけにしてください。

1. **最初にClaudeにあいさつする**：司令塔のプロジェクトにこのガイドのファイルを入れて、コンテキストとして渡します。そのうえで自分のこととプロジェクトの状況を伝え、AIと一緒に進めます。
2. **操作はAIに任せてよいが、中身は理解する**：できるかぎりの操作をAIに任せて大丈夫です。ただし、AIが何をしているのかを自分で説明できる状態にしてください。分からなければ「今のコマンドは何をしていますか？」「なぜこの書き方なのですか？」と、AIに深掘りして質問します。
3. **資料もAIに作ってもらう**：計画書、設計書、CLAUDE.md、SKILL.md、このアプリの説明（README）などもAIに作ってもらい、自分で読んで直します。形式はすべてマークダウンにします。

最初のあいさつの例です。【 】を書きかえて使ってください。

```text
こんにちは。これから「n重振り子シミュレーター」の開発課題を進めます。
課題の内容は、このプロジェクトに入れた n-pendulum-guide.md にまとめてあります。
私について：【得意なこと、これまでの経験、不安なこと】
今の状況：【例：まだ何も始めていません】
このガイドに沿って、ステップ1から一緒に進めてください。
あなたが何をしているかも理解したいので、作業のあとに短く説明してください。
まず、ステップ1で私がやることを順番に教えてください。
```

**なぜマークダウンで資料を作るのか**

- AIが読みやすく、書きやすい。見出しや箇条書きで、文章の構造がそのまま伝わる
- ただのテキストなので、Gitで変更の差分が見やすく、どのエディタでも開ける
- GitHubやVS Codeで、表やコードがきれいに表示される
- CLAUDE.mdやSKILL.mdもマークダウンなので、書き方を覚えるとAIへの指示も上手になる

| `- 項目` | 箇条書き |
| `1. 項目` | 番号つきの箇条書き |
| `**太字**` | 太字 |
| `` `コード` `` | 文中のコード |
| ```` ``` ```` で囲む | 複数行のコード。最初の ```` ``` ```` の後ろに言語名を書く（例：python） |
| `\| 列 \| 列 \|` | 表 |
| `- [ ] やること` | チェックボックス。`[x]` で完了 |
| `[文字](URL)` | リンク |

## 全体の流れ

5つのステップを順番に進めます。目安の期間は参考です。

| ステップ | やること | 提出するもの | 目安 |
| --- | --- | --- | --- |
| 1. 環境構築 | VS Code、Git、Claude Code、CLAUDE.md、skillsを整える | GitHubリポジトリのURL | 2〜3日 |
| 2. 設計・計画書 | 何をどう作るかを文章にする | docs/design.md と docs/plan.md | 3日 |
| 3. 実装 | 5つの段階に分けて作る | 段階ごとのプルリクエスト | 2週間 |
| 4. デプロイ | インターネットに公開する | 公開URL | 3日 |
| 5. ブラッシュアップ | 見た目を磨き、ふりかえりを書く | 完成版のURLとふりかえり | 1週間 |

アプリの作りは、画面（TypeScript）が条件を送り、計算サーバー（Python）が振り子の動きを計算して返し、画面がそれを描く、という形です。

## ステップ1 環境構築

AIと一緒に開発するための道具をそろえ、AIにプロジェクトのルールを教えるステップです。

1. **道具を入れる**：VS Code、Git、Python 3.12以上、Node.js（LTS版）、uv（Pythonのパッケージ管理）を入れます。あわせて、ClaudeのデスクトップアプリかWebで司令塔用のプロジェクトを作り、このガイドを入れておきます。
2. **Claude Codeを入れる**：Claude Proの契約で使えます。VS Codeの拡張機能として入れて、ログインします。実装やターミナルの操作に使い、モデルはSonnetにします。
3. **GitHubリポジトリを作る**：名前は `n-pendulum` とし、次のフォルダを作ります。
4. **CLAUDE.mdを書く**：AIが毎回最初に読む、プロジェクトの説明書です。下の見本とこのガイドを渡してAIに作ってもらい、自分で読んで納得できる内容に直してください。
5. **skillを1つ作る**：よく頼む作業の手順書です。これもAIに作ってもらいます。`.claude/skills/step-report/SKILL.md` に「ステップ報告を書く手順」を作ります。

```text
n-pendulum/
├── backend/      Python（計算とAPI）
├── frontend/     TypeScript（画面）
├── docs/         設計書・計画書・報告
├── .claude/skills/
├── CLAUDE.md
└── README.md
```

CLAUDE.mdの見本です。

```markdown
# n-pendulum
n重振り子のシミュレーター。計算はPython、画面はTypeScript。

## 構成
- backend/：FastAPI。物理計算は backend/physics/ に置く
- frontend/：Vite + TypeScript。描画はCanvas

## ルール
- 物理計算を変えたら、必ず pytest を実行する
- 数式を変えるときは、docs/design.md の式と合っているか確かめる
- 1回の変更は小さくする。終わったら変更点を3行で説明する
- 分からないことは推測で進めず、質問する

## よく使うコマンド
- テスト：cd backend && uv run pytest
- 画面の起動：cd frontend && npm run dev
```

**完了の条件**

- [ ] Claude Codeから「このプロジェクトの構成を説明して」と聞くと、CLAUDE.mdの内容どおりに答える
- [ ] 空のフォルダ構成とCLAUDE.md、skillがGitHubに上がっている
- [ ] リポジトリのURLを送った

## ステップ2 設計・計画書

コードを書く前に、何をどう作るかを文章にするステップです。AIと相談しながら書いてかまいませんが、数式は自分で確かめてください。

**docs/design.md（設計書）に書くこと**

- **物理モデル**：n個の振り子をつないだ系です。各節の角度 θi、角速度 ωi、質量 mi、長さ li と重力 g の定義、運動方程式を書きます。ラグランジアンから導き、「行列 A(θ) × 角加速度 ＝ b(θ, ω)」の形にまとめてください
- **計算方法**：毎ステップ、NumPyで連立一次方程式を解いて角加速度を求め、4次のルンゲ・クッタ法（RK4）で進めます。RK4は自分で実装します。時間刻み dt をいくつにするかと、その理由も書きます
- **入れ替えられる作り**：運動方程式の部分とRK4の部分を分けてください。あとで別の物理（例：三体問題）に差し替えられるようにするためです
- **正しさの確かめ方**：下の力学的エネルギー E が保存されること、n＝1で単振り子、n＝2で二重振り子の式と一致することをテストにします
- **上限**：nは1〜8とします。nが大きいと計算が不安定になりやすいためです
- **画面**：何を表示し、何を操作できるか。手書きのスケッチの写真でもかまいません
- **API**：画面と計算サーバーの間でやりとりするデータの形

```math
E = \frac{1}{2}\sum_{j=1}^{n}\sum_{k=1}^{n}\mu_{\max(j,k)}\,l_j l_k\,\omega_j\omega_k\cos(\theta_j-\theta_k) \;-\; g\sum_{j=1}^{n}\mu_j\,l_j\cos\theta_j,\qquad \mu_j=\sum_{i=j}^{n}m_i
```

APIは、まず次の1つを基本にします。変えたい場合は理由を設計書に書いてください。

| 項目 | 内容 |
| --- | --- |
| 呼び出し | `POST /api/simulate` |
| 送るもの | 振り子の数 n、各節の初期の角度・角速度・質量・長さ（それぞれn個の配列）、重力、dt、計算する秒数 |
| 返るもの | 時刻ごとの角度と角速度（n個ずつ）の配列、エネルギーの配列、先端の加速度の大きさの配列 |

**docs/plan.md（計画書）に書くこと**

- ステップ3の5つの段階を、それぞれ「作るもの」「完了の条件」「予定日」で書きます
- リスクを1〜3個書きます（例：長い時間を計算するとデータが大きくなる）

**完了の条件**

- [ ] design.md と plan.md がGitHubに上がっている
- [ ] 運動方程式を、AIの答えとは別に自分で確かめた（確かめた方法を1行で書く）
- [ ] 報告を送り、辻村から「進めてOK」の返事をもらった

## ステップ3 実装

5つの段階に分けて作ります。1つ終わるごとにブランチを切ってプルリクエストを出し、確認を受けてから次に進みます。

| 段階 | 作るもの | 完了の条件 |
| --- | --- | --- |
| 3-1 物理エンジン | Pythonで、n重に対応した運動方程式（行列の形）とRK4を実装する（NumPyのみ使用） | pytestが通る。n＝2で、dt = 0.001秒で30秒計算して、エネルギーのずれが0.01%以内 |
| 3-2 API | FastAPIで `POST /api/simulate` を作る | ブラウザの `/docs` 画面から呼び出して、結果が返る。おかしな入力（負の長さなど）はエラーになる |
| 3-3 描画 | Vite + TypeScriptで、Canvasに振り子を描く | APIの結果を読んで、振り子がなめらかに動く |
| 3-4 操作 | ブラウザで条件を設定する画面。振り子の数 n（1〜8）を選べる。角度・角速度・長さ・質量・重力を、スライダーと数値入力の両方で変えられる。再生・停止・リセットのボタン | 値を変えると、新しい条件で動きが変わる。範囲外の値は入力できない。スマホの幅でも操作できる |
| 3-5 軌跡とマーク | 先端のおもりが通った跡を、線で残す。先端の加速度がいちばん大きかった地点（いちばん強く振り回された地点）に、マークを付ける | 軌跡が少しずつ消えていく表示になっている。マークの横に、加速度の大きさと時刻が表示される。その値がテストで確かめてある |

3-1のテストには、次の4つも入れてください。

- n＝1で、小さい角度のときに単振り子の周期と合うこと
- n＝2で、二重振り子の式をそのまま書いた別の実装と、結果が一致すること
- 真下で止まった状態（すべて0）から始めると、動かないこと
- n＝1から8まで、どれもエラーなく計算できること。エネルギーのずれがどのくらいになるかも記録する

AIとの進め方のおすすめです。

1. 段階を始める前に、Claude Codeに「この段階の進め方を計画して」と頼み、計画を読んでから実行させる
2. テストを先に書いてもらい、そのあと実装してもらう
3. できたコードは、自分で読んで説明できる状態にしてからコミットする

プルリクエストには、何を作ったか、どう確かめたか、AIに何を頼んだかを書いてください。

## ステップ4 デプロイ

作ったアプリを、URLを開けばだれでも見られる状態にするステップです。Google Cloudを使います。

| 部分 | 置く場所 | やること |
| --- | --- | --- |
| 計算サーバー（Python） | Cloud Run | Dockerfileを書き、コンテナとして公開する |
| 画面（TypeScript） | Firebase Hosting | `npm run build` の結果を公開し、`/api` へのアクセスをCloud Runに渡す設定をする |

**始める前に必ず相談してください。** Cloud Runを使うには、Google Cloudへの支払い情報の登録が必要です。無料枠の中で収まる使い方をしますが、登録をどうするかは辻村と塩沢さんと決めてから進めます。

安全のために守ることです。

- APIキーやパスワードを、コードやGitHubに書かない
- 1回の計算の秒数と n に上限をつける（例：60秒まで、nは8まで）。大きすぎる計算を送られても止まらないようにするためです
- Cloud Runの最大インスタンス数を1にして、料金が増えないようにする

**完了の条件**

- [ ] 公開URLを、パソコンとスマホの両方で開いて動くことを確かめた
- [ ] READMEに、公開の手順を自分の言葉で書いた
- [ ] 公開URLを送った

## ステップ5 ブラッシュアップ

動くものを、人に見せたくなる作品に磨くステップです。次の中から2つ以上を選んでください。自分の案でもかまいません。

- **A カオスを見せる**：初期の角度を0.001ラジアンずつずらした振り子をたくさん同時に動かし、だんだんバラバラになる様子を描く
- **B 色と光**：節ごとに色を変え、速さによって軌跡の色や太さを変える。暗い背景に光る線で描く。nを増やすと、鎖やムチのようにしなる動きを見せられる
- **C グラフ**：エネルギーの変化や、θ1とθ2の関係をグラフで添える
- **D 説明ページ**：使った数式とその意味を、画面の中で読めるようにする
- **E 速さの改善**：計算やデータの送り方を工夫して、長い時間でもなめらかに動かす

**できれば挑戦：ゲームにする**

余裕があれば、シミュレーターを遊べる形にしてみてください。必須ではありません。案を3つ挙げます。

- **的当て**：画面に的を置き、先端のおもりが的を通るように最初の角度を決める。少ない回数で当てるほど高得点
- **予想クイズ**：2つの振り子のうち、どちらが先に一回転するかを当てる
- **お絵かき**：軌跡でお題の形（円やハート）に近い線を描く。近さを点数にする

ゲームにする場合は、作る前にルールと得点の計算方法を docs/design.md に書き足してください。

最後に docs/retrospective.md（ふりかえり）を書きます。

- 工夫したところと、困ったところ
- AIが役に立った場面と、AIが間違えた場面。間違いにどう気づいたか
- CLAUDE.mdやskillを、途中でどう直したか
- 次に作ってみたいもの

**完了の条件**

- [ ] 選んだ改善が公開URLに反映されている
- [ ] READMEに、スクリーンショットと公開URL、使い方が書いてある
- [ ] ふりかえりを送った

## ＋α 発展のアイデア（必須ではありません）

ここから先は、ステップ5まで終わって余裕があるときの例です。やらなくても課題は完了です。興味があるものがあれば、ひとつ選んで相談してください。

| 発展 | 内容 | 関係する分野 |
| --- | --- | --- |
| 摩擦と空気抵抗 | 関節の摩擦や空気抵抗を入れて、だんだん止まる現実に近い動きにする | 機械力学 |
| 棒にかかる力の表示 | 各節の棒を引っぱる力（張力）を計算して、色で見せる。どこがいちばん壊れやすいかが分かる | 材料力学・強度設計 |

## 提出と質問のしかた

各ステップが終わったら、次の形で報告を送ってください。短くてかまいません。

```text
【ステップ】（例：3-1 物理エンジン）
【できたこと】
【確かめた方法】
【AIに頼んだこと】
【困ったこと・質問】（なければ「なし」）
【URL】（リポジトリ、プルリクエスト、公開URLなど）
```

質問は、いつでも文章で送ってください。次の3つがあると、早く答えられます。

- やりたかったこと
- 実際に起きたこと（エラーの文章やスクリーンショット）
- 試したこと

1時間考えても進まないときは、途中のままで質問して大丈夫です。途中で相談できることも、仕事では大事な力です。

## ステップ3の5つの段階

### 3-1 物理エンジン（11/27〜11/27）

**作るもの**
- `backend/physics/integrator.py`：RK4（自分で実装）
- `backend/physics/system.py`：差し替え用の型（Protocol）
- `backend/physics/pendulum.py`：n重振り子の A(θ)、b(θ, ω)、エネルギー、先端の加速度
- `backend/tests/`：design.md 5章のテスト（先に書く）

**完了の条件**
- `uv run pytest` がすべて通る
- n=2、dt=0.001、30秒で、エネルギーのずれが 0.01% 以内
- 単振り子の周期、二重振り子の別実装との一致、静止状態、n=1〜8 のテストが入っている
- n=1〜8 のエネルギーのずれを docs/energy-drift.md に記録した

### 3-2 API（11/30〜12/1）

**作るもの**
- `backend/main.py`：FastAPI の `POST /api/simulate`
- 入力のチェック（design.md 6章の範囲）と、1/60秒ごとの間引き

**完了の条件**
- ブラウザの `/docs` から呼び出して、結果が返る
- 負の長さ、n=9、配列の長さが合わないなどの入力が 422 エラーになる（テストあり）

### 3-3 描画（12/2〜12/4）

**作るもの**
- `frontend/`：Vite + TypeScript のひな形
- Canvas に振り子を描き、API の結果を時刻に合わせて再生する部品

**完了の条件**
- 固定の条件で API を呼び、振り子がなめらかに動く（1秒に60コマ）
- 計算サーバーの時刻と画面の時刻がずれない

### 3-4 操作（12/7〜12/9）

**作るもの**
- n の選択（1〜8）、各節の θ・ω・m・l と g のスライダー＋数値入力
- 再生・停止・リセットのボタン

**完了の条件**
- 値を変えて再生すると、新しい条件で動きが変わる
- 範囲外の値は入力できない
- スマホの幅（360px）でも操作できる

### 3-5 軌跡とマーク（12/10〜12/11）

**作るもの**
- 先端の軌跡（古いところほど薄くなる）
- 先端の加速度が最大の地点の ✕ マークと、大きさ・時刻の表示

**完了の条件**
- 軌跡が少しずつ消えていく
- マークの横に加速度の大きさと時刻が出る
- 最大値の計算が正しいことをテストで確かめた（例：n=1 で答えが分かる条件）

## リスク

| リスク | 起きること | 対策 |
| --- | --- | --- |
| データが大きくなる | 60秒・n=8 をそのまま返すと数MBになり、表示が遅い | 1/60秒ごとに間引く（design.md 3.4）。それでも重ければ数値の桁を減らす |
| n が大きいと計算が遅い・不正確 | n=8 で長く計算すると時間がかかる。カオスでエネルギーがずれる | 上限（n≤8、60秒）をつけ、ずれを記録して画面に出す。遅ければ ステップ5のEで改善 |
| 物理の式の間違いに気づきにくい | それらしく動くので、式が違っていても見た目では分からない | エネルギー保存と、n=1・n=2 の既知の式との比較を、実装より先にテストとして書く |
